# Shop API · TesterHub

Небольшой работающий API магазина для практики QA: товары, заказы, OpenAPI и интерактивная документация **Scalar**. Работает локально, без базы данных, Docker и регистрации в Scalar.

Автор — **Евгений Сычёв**: [sychev.me](https://sychev.me). Практические курсы и задания — на [LMS TesterHub](https://lms.testerhub.ru). Бесплатный курс «Shift-left для QA» готовится к запуску; этот репозиторий — его учебный проект.

## Быстрый старт

Нужны **Node.js 24 LTS** (npm входит в комплект), **Git** и интернет для первоначальной установки зависимостей. Скачать: [Node.js](https://nodejs.org/en/download), [Git](https://git-scm.com/downloads).

Откройте терминал в папке, где хотите хранить проект. Команды выполняйте по одной:

```bash
git clone --branch v1.0.1 --single-branch https://github.com/kreotiff-dev/shop-api.git
cd shop-api
npm ci
npm start
```

Затем откройте **[http://127.0.0.1:4010/docs](http://127.0.0.1:4010/docs)**. Сервер остаётся работать в терминале; остановка — **Ctrl+C**. Корневой адрес `/` тоже переводит в документацию.

В Windows, если PowerShell блокирует `npm.ps1`, используйте `npm.cmd ci` и `npm.cmd start`. Системную политику выполнения менять не требуется.

### Первые запросы

В Scalar выберите **GET /products**, откройте **Test Request**, установите `limit=1` и отправьте запрос. Ожидаются **200**, один товар в `items` и `total: 3`.

Повторите с `limit=0`: ожидаются **400**, `code: "BAD_LIMIT"` и пояснение допустимого диапазона. Это корректное отклонение неверного запроса, а не поломка сервера.

До отправки запроса Scalar показывает описание и примеры из спецификации. После отправки смотрите **фактический ответ** и HTTP-статус. Пример в документации сам по себе не подтверждает работу сервера.

Можно использовать Postman или другой клиент. Базовый адрес: `http://127.0.0.1:4010/api/v1`. Например:

```bash
curl "http://127.0.0.1:4010/api/v1/products?limit=1"
```

В Windows PowerShell используйте `curl.exe` вместо `curl`.

## Что внутри

| Файл | Назначение |
|---|---|
| `server.mjs` | HTTP-сервер на JavaScript/Node.js; менять код для вводного урока не нужно |
| `openapi.yaml` | Одна базовая спецификация API |
| `public/docs.html` | Локальный интерфейс Scalar |
| `package.json`, `package-lock.json` | Команды и закреплённые зависимости |
| `test/`, `.github/workflows/verify.yml` | Служебные проверки работоспособности учебного проекта |

Сервер умеет получать список/карточку товара, создавать и получать заказы. Три начальных товара заданы в коде, заказы хранятся в памяти и исчезают после перезапуска. Авторизации и интерфейса магазина нет. Сервер слушает только `127.0.0.1` — ваш компьютер.

Scalar и спецификация отдаются локально. После `npm ci` для обычной работы не нужен CDN или внешний прокси запросов. Сам Scalar не проверяет корректность всей реализации API. В учебном интерфейсе скрыты предложения генерации SDK/MCP, AI и панель разработчика; оставлены документация, схемы, YAML и отправка запросов. Основной пример кода — cURL; остальные языки доступны через меню More.

## Как выдаются материалы разных курсов

**Этот репозиторий — небольшой общий стартовый проект.** Он не содержит продвинутых версий `safe`/`breaking`, ответов к заданиям, склада или будущего интерфейса маркетплейса.

- В уроке дана конкретная версия проекта, например `v1.0.0`. Она фиксирует файлы, на которых проверены инструкции. Не обновляйте её посреди курса командой `git pull` без указания в уроке.
- Дополнительные материалы выдаются **в нужном уроке отдельным ZIP-пакетом** из [релизов проекта](https://github.com/kreotiff-dev/shop-api/releases). Для бесплатного курса — `shift-left-free-exercises-v1.0.0.zip`.
- В начале эти упражнения скачивать не нужно. Когда дойдёте до указанного урока, распакуйте содержимое ZIP в корень своей копии Shop API. Пакет добавит подписанную папку `exercise/`, правила линтера и готовый workflow; сервер менять не потребуется.
- Для другого курса будет свой пакет с отдельным именем и версией. Новые несовместимые версии самого API получат новый тег. Не нужно изучать общий монорепозиторий или переключать ветки до знакомства с Git.

Команды `lint:*` в package.json подготовлены для следующих уроков и требуют соответствующий пакет упражнений. На этапе первого запуска используйте только `npm ci` и `npm start`.

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| `node` или `git` не найден | Установить инструмент, заново открыть терминал и проверить `node --version`, `git --version` |
| Нет package.json / server.mjs | Перейти в папку `shop-api` командой `cd shop-api` |
| Порт 4010 занят | Остановить прежний процесс или запустить `npm start -- 4011`, открыть `http://127.0.0.1:4011/docs` |
| Документация не открывается | Проверить, что npm ci завершился успешно и терминал с сервером не закрыт |
| Соединение отклонено | Проверить адрес и порт из вывода запуска; `127.0.0.1` означает текущий компьютер |

При другом порте спецификация, отдаваемая сервером по `/openapi.yaml`, получает актуальный адрес API автоматически. Файл на диске остаётся с исходным портом 4010.

## Для следующих упражнений

`npm run start:buggy` запускает режим с намеренными дефектами. Перед переключением остановите обычный сервер Ctrl+C. Используйте режим только по указанию урока.

Проект учебный, с намеренными ограничениями и несоответствиями: например, объявленный `category` пока не фильтрует товары. Обычный режим не является эталоном всей спецификации. Это материал для расследований, а не готовый backend реального магазина.

## Проверка проекта

```bash
npm test
```

Проверяются выдача Scalar и OpenAPI, первые запросы, создание/чтение заказа, сброс данных и режим с дефектом цены. Эти проверки подтверждают работу учебного пакета, а не прохождение курса учеником.

Об ошибке в проекте можно сообщить через [Issues](https://github.com/kreotiff-dev/shop-api/issues). Не прикладывайте рабочие токены, личные данные и непубличные спецификации.
